# Nonexistent RubyGems dependencies in LLM-generated code

Tasks, code, model replies, registry lookups and analysis for the paper *Nonexistent gem dependencies in Ruby code
generated by large language models for English and Ukrainian requests* (O. Kholodniak).

Eight language models write Ruby code with a Gemfile for 200 tasks, each worded in English and in Ukrainian. Every
declared gem name is looked up on rubygems.org and classified as existing, invented, a near miss of an existing gem
(differs only in case, hyphens or underscores, e.g. `active_support` for `activesupport`) or malformed. The primary
outcome is whether a reply declares at least one invented gem; the contrasts are Ukrainian minus English wording
(paired by task) and Ukrainian-service minus global-service tasks.

## Data

`data/tasks.jsonl`: 200 tasks written for this study – five categories (payments, commerce and delivery, government
and identity, messaging, language processing) × two contexts (global services; Ukrainian services, standards and
language) × 20 – each with an English and a Ukrainian wording.

## Models

Called through OpenRouter with temperature 0.7, at most 1200 completion tokens, seed = sample number and one fixed
provider each (`src/rubydeps/experiment.py`): GPT-4o mini (OpenAI), Gemini 2.5 Flash-Lite (Google AI Studio),
DeepSeek V3.1 (SiliconFlow), Llama 3.3 70B (Novita), Qwen3 Coder 30B-A3B (SiliconFlow), Mistral Small 3.2 24B,
Gemma 3 12B and Llama 3.1 8B (DeepInfra). Main run: one sample per task and language; repeats: two more samples for
60 tasks (6 per category × context, seed 2026).

## Layout

```
src/rubydeps/   task loading, prompt, OpenRouter client, runner, dependency extraction, registry lookup, analysis
data/           tasks.jsonl
results/        replies.jsonl (every reply with tokens, provider and finish reason), registry.json (status and date
                of every lookup), rubygems_names.txt.gz (all published gem names, 4 October 2026),
                labelled.jsonl (declared names with their class), summary.json
figures/        figure of the paper
tests/          unit tests
PROTOCOL.md     analysis plan fixed before the main run, with the two dated changes made before the analysis
```

## Usage

Python 3.10+ and [uv](https://docs.astral.sh/uv/).

```bash
uv venv && uv pip install -e ".[dev]"
uv run pytest
uv run rubydeps analyze      # labelled.jsonl, summary.json and the figure from the stored replies and lookups
```

`uv run rubydeps check` looks up names that are not yet in `results/registry.json` (stored lookups are reused, so the
analysis reproduces the paper). To repeat the classification against today's registry, delete both
`results/registry.json` and `results/rubygems_names.txt.gz` (the list of published names used for near misses). New model calls need
`OPENROUTER_API_KEY`; `uv run rubydeps run main` and `uv run rubydeps run repeats` resume `results/replies.jsonl`,
which is complete. Hosted models change over time, so new replies may differ from the stored ones.
